# Taste UI redesign

User requested a whole-app redesign with Taste and reiterated the request to proceed. Implementation uses the existing Next.js, Tailwind and Geist stack, without new runtime dependencies.

## Design and scope

Retain Brightloop's wordmark, URLs, navigation labels, form order, service calls, authorization and honest unavailable states. Replace the pale indigo, small low-contrast text, simulated dashboard hero, and disconnected staff shell with an emerald/graphite system: light content surfaces, dark workspace navigation, readable 14–16px body copy, restrained borders and deliberate spacing. Public pages use a large left-aligned headline and an honest workflow diagram. Authentication uses a dark brand panel beside the existing forms.

The shared stylesheet owns presentation across public, auth and customer routes; identity shell and forms own staff presentation. Domain components retain all financial and ownership checks. No database or API changes. Cross-module presentation work is authorized by the user's whole-UI request.

## Review focus

Long names and identifiers must wrap. Navigation must identify only the current route and remain labelled when collapsed. Search focus must remain visible. Unavailable data must never display zero financial totals. At 320px the page must stay within the viewport while tables scroll inside their containers. Printed invoices must keep document content and omit navigation.
